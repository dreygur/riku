# Code map

Where each job lives, so you can open the right file without searching. One section per crate: its job, riku crate dependencies, entry points, then one line per module or directory, then gotchas (things that surprise someone changing the code).

Keep it true. Any commit that adds, moves, renames or changes the contract of a module updates this file in the same commit. A line here is a pointer, not a spec: read the code before relying on a contract.

Crate layers, lowest first:

- Leaf: riku-util, riku-config, riku-error, riku-http, riku-bundle, riku-args
- Drivers and renderers: riku-container, riku-nginx, riku-caddy, riku-route, riku-plugins
- Services: riku-supervisor (must not call deploy or cli), riku-deploy
- Entry points: riku-cli, riku-dashboard, riku-remote, riku (server binary), riku-client (`rk`, laptop only)


## riku
Job: the `riku` binary. Parses argv, picks local vs forwarded target, runs local commands. Depends on: riku-config, riku-util, riku-error, riku-nginx, riku-plugins, riku-supervisor, riku-deploy, riku-cli, riku-dashboard. Used by: tests (`riku-route` is a dev-dependency only).
Entry: `fn main` in `src/main.rs`.

- `src/main.rs`: init tracing once the command is parsed (stderr, `RUST_LOG`, default info for `supervisor`, `router-helper` and `dashboard`, warn otherwise, escapes only on a terminal), `cli::ssh_command::process_argv`, `parse` (help heading names the implied server), `route::target_for`, `run_or_forward`, then `RikuPaths::from_env` and `cli::dispatch::run_local` (or `dashboard::run`). An error is printed as `■  <error>` on stderr and exits 1. Contract: `SSH_ORIGINAL_COMMAND` set means "running as the ssh forced command", which never forwards again.
- `src/lib.rs`: facade of `pub use` aliases (cli, config, dashboard, deploy, error, nginx, plugins, supervisor, util) so integration tests reach every crate as `riku::x`. No logic.
- `Cargo.toml`: wires the `[[test]]` targets `integration_tests` and `stress_tests` to `../../tests/` and the bench `core_benchmarks` to `../../benches/`.

Gotchas:
- `Commands::RouterHelper` is handled before `RikuPaths::from_env`: the helper runs as a systemd system service with no `HOME`.
- `riku::cli` re-exports `riku_args` and `riku_remote` modules (see riku-cli lib.rs), so `cli::remote::flow` in main.rs is riku-remote code.
- Unit tests of this crate: none in `src/`; tests live in `tests/` (see tests section).

## riku-client
Job: builds the `rk` laptop-only binary (package riku-client, bin `rk`). Depends on: riku-args, riku-remote, riku-util (output rail only). Used by: nobody (leaf binary).
Entry: `fn main` in `src/main.rs`.

- `src/main.rs`: `run`: parse, reject `--local`, `check_supported`, `target_for`, `run_or_forward`; a local error prints as `■  <error>` and exits 1 (a forwarded command exits with the server's code). Contract: never runs server code, never the ssh forced command (`via_ssh: false`, `local: false`).
- `src/parse.rs`: `parse`. Refusal of a server-only command is checked before clap parses the command's own args, so `rk init --force` is refused, not "unknown flag". Handles `rk help <cmd>`.
- `src/local.rs`: `check_supported` (uses `riku_args::placement::client_rule`), `run_without_server`: runs `server`, `plugin`, `quickstart` and `plugins scaffold|keygen|sign` locally; any other command with no target is the "no server selected" error listing registered servers.
- `tests/deps.rs`: runs `cargo tree --offline` and fails if riku-client or riku-args link a server crate or `reqwest` (riku-args also may not link riku-config).

Gotchas:
- `rk` must stay small: never add a dependency on riku-deploy, riku-supervisor, riku-nginx, riku-plugins, riku-dashboard, riku-cli, riku-http or reqwest (`tests/deps.rs` enforces it). That is why riku-http is a separate crate.
- `rk` dashboard works only in its remote form (`run_remote` in riku-remote), local `dashboard` falls to the no-server error.

## riku-remote
Job: laptop-side behaviour shared by `riku` and `rk`: named server list, ssh forwarding, remote dashboard client, client plugins, quickstart, plugin authoring. Depends on: riku-args, riku-bundle, riku-util. Used by: riku-cli (re-exports as `cli::remote`, `cli::client_plugins`, `cli::quickstart`, `cli::routing`), riku-client.
Entry: `remote::flow::run_or_forward` (`src/remote/flow.rs`), `remote::route::target_for`, `remote::route::implied_server`, `remote::server_cmd::run`, `plugin_author::cmd_plugins_*`, `quickstart::cmd_quickstart`, `plugin_cmd::run_plugin`.

- `src/remote/flow.rs`: `run_or_forward`, `Outcome`. Order: apply app hint, client plugin, then (`Target::Remote`) remote dashboard or `forward`, else `Outcome::Local`. A forwarded command calls `process::exit` with the remote exit code.
- `src/remote/route.rs`: `target_for`, `implied_server`, `forward`, `is_plugin_authoring`. Contract: server list and `git remote -v` are read only for forwarded commands and `dashboard`, never under `SSH_ORIGINAL_COMMAND`.
- `src/remote/target.rs`: `Target`, `Selection`, `Source`, `resolve`, `registered_names`. Picks server from `-s`, git remote, then default. `--local` and server-side invocation always mean local.
- `src/remote/forward.rs`: `ssh_args`, `run`, `server_arg_positions`, `strip_target_args`, `needs_tty`. Contract: destination is a validated `SshAddress` after `--`; remote command is one `shlex::try_join` argument; no local shell.
- `src/remote/git_remote.rs`: `read_remotes`, `read_remotes_in`, `parse_remotes`, `RemoteRef`. Only scp-style remotes. Reads the repo's git config, so it is untrusted: only matched against registered servers, never adds an ssh target.
- `src/remote/store.rs`: `servers_path`, `load`, `save`. Reads/writes `${XDG_CONFIG_HOME:-$HOME/.config}/riku/servers.toml` (not `dirs::config_dir`), dir 700, file 600 through riku-util `write_private` (exclusive temp, fsync, rename), entries revalidated on load.
- `src/remote/types.rs`: `Server`, `ServerList`; re-exports `ServerName`, `SshAddress` from riku-args (validation lives there).
- `src/remote/server_cmd.rs`: `riku server add|list|remove|default`; `run_at(path, repo_dir, cmd)` is the testable form. `add` then runs `server_add.rs`: `key_install.rs` sends this machine's public key (type and data only, one quoted argument) as `ssh -t <admin> sudo riku deploy-key add --user <user from the address>`, or prints that command without an admin; `remote_add.rs` adds the repo's `riku` remote unless one exists. `add` prints on the rail: intro after the entry is saved, a step per stage, outro and a `Deploy` summary only when the key step did not fail.
- `src/remote/dashboard/`: remote `riku dashboard`. One ssh ControlMaster to the admin login, sudo to the deploy user, token sent on stdin only after `READY_MARKER`, local port forward to 127.0.0.1, browser opened. Key: `run_remote` (mod.rs), `check_remote_flags` (flags.rs), `Handshake` state machine (handshake.rs), `remote_script.rs` (script text, markers), `ssh_master.rs` (arg builders, control socket in private temp dir), `sudo.rs` (password via /dev/tty, zeroed), `stop.rs` (SIGTERM only), `interrupt.rs`, `session.rs`, `events.rs`, `browser.rs`, `ended.rs`.
- `src/client_plugins/`: executables in `$HOME/.riku/client-plugins/<command>`. `try_execute_client_plugin`, `cmd_plugin_list`, `cmd_plugin_exists`; `discovery.rs` reads `HOME` once, `client_plugin_path_in`/`list_client_plugins_in` take the home. Plugin argv: `$1` server address (empty if local), `$2` app, `$3` full command, `$4+` extras.
- `src/routing.rs`: `get_plugin_command` (which `Commands` a client plugin may override; `Rollback`, `Init`, `Backup`, `Doctor`, plugin/hook/agent commands cannot), `build_plugin_args`.
- `src/plugin_cmd.rs`: dispatch for `riku plugin list|exists`.
- `src/plugin_author/`: `plugins scaffold|keygen|sign` on the author's machine, `Program` (Riku or Rk) sets hint wording. Secret key created 0600 up front and never printed; signing covers the entry file only (see riku-bundle); `skeleton.rs` holds the manifest and entry text per `SeamType`.
- `src/quickstart/`: `cmd_quickstart` writes a sample app (`Runtime` in `scaffold.rs`) into the current directory, `git init`s, prints the remote step (`--remote`, else the default registered server, else `rk server add`) and `git push`. `scaffold_into(base, ...)` takes the directory so tests do not change cwd.
- `src/lib.rs`: `pub(crate)` aliases `cli`, `cmds`, `help`, `placement` (riku-args) and `util` (riku-util).

Gotchas:
- Two homes: server list under XDG/`~/.config/riku`, client plugins under `~/.riku/client-plugins` (note `HOME`, not `RIKU_ROOT`).
- Server-side `riku` also links this crate (through riku-cli), so a change here changes the forced-command path; keep `via_ssh` handling intact.
- Name validation for servers is in riku-args (`address.rs`), not here; `store::load` reuses it via `TryFrom`.
- Dashboard URL (token included) is visible in the local `open`/`xdg-open` argv for an instant; documented and accepted in `browser.rs`.

## riku-util
Job: shared leaf helpers: validation, fs, env/Procfile parsing, cron, display, keys, naming. Depends on: none. Used by: riku-caddy, riku-cli, riku-container, riku-dashboard, riku-deploy, riku-nginx, riku-plugins, riku-remote, riku-route, riku-supervisor, riku. Also linked by `rk`, so no heavy deps.
Entry: re-exports in `src/lib.rs`: `validate_app_name`, `ensure_path_within`, `parse_procfile`, `parse_settings`, `write_config`, `write_atomic`, `write_private`, `create_private_dir`, `get_free_port`, `print_table`, `setup_authorized_keys`.

- `src/validation.rs`: `sanitize_app_name`, `validate_app_name`, `existing_app` (error, no output), `exit_if_invalid` (prints the CLI hints, then returns the error; despite the name it never exits), `ensure_path_within`, `REPO_SUFFIX`. Contract: app name keeps only alnum `.` `_` `-`, rejects `..`, dot-only, trailing `.git`; `ensure_path_within` canonicalizes both paths and errors if either does not exist.
- `src/file_names/`: names derived from an app: `worker.rs` (`WorkerName` `<app>@<kind>.<n>`, config file `<id>.toml`), `copy_socket.rs` (`<app>@<n>.sock`). `@` is the separator because neither app names nor kinds may contain it; do not build these names by hand.
- `src/fs.rs`: re-exports `fs/atomic.rs` `write_atomic` (tmp + fsync + rename, mode 0666 less umask) and `write_private` (0600 from creation); the temp file `.<name>.tmp-<pid>-<seq>` sits beside the destination, `seq` is a process wide counter, and it is created with `create_new` plus `O_NOFOLLOW`, so a taken name (leftover file or planted link) is skipped, never opened, and only a temp this call created is removed on error. `fs/symlink.rs` `replace_symlink` makes its temp link under the same per call name (shared `next_temp_seq`, `temp_path`) and skips a taken name instead of removing it, so threads swapping one link never collide. Also `create_private_dir`, `restrict_to_owner`, `copy_dir_recursive`, `count_files`, and `presence` (`Presence::Present`, `Missing`, or `Unknown` on a permission error, where `Path::exists` would say missing).
- `src/write_dir.rs`: `check_write_dir`: root writes only into a real dir owned by `owner` with no group/other write.
- `src/socket_dir.rs`: uWSGI socket dir, mode 2750 with shared group; `prepare`, `ensure_exists`, `group_id`. Refuses a non-directory (symlink) before chown/chmod.
- `src/env.rs`: `parse_settings` (KEY=VALUE with `$VAR` expansion, strips control chars; a line without `=` is an error naming file and line, and the caller's map is left untouched), `write_config` (atomic, 0600), `expandvars`.
- `src/runtime_markers.rs`: `BUNDLED_RUNTIMES`, the runtime plugins riku can install by name, and `needed_runtime`, the shell runtime an app's marker files call for (shared by server and laptop code).
- `src/flag.rs`: `is_on`, `https_only`, `https_only_warning`: only explicit yes values are on, typos are off.
- `src/nginx_validation.rs`: `validate_env_vars`, `print_env_warnings`: warns only, the route gate decides what reaches config.
- `src/procfile.rs`: `parse_procfile` (None if file missing; any bad line fails the whole parse), `is_valid_kind`. Cron kinds start with `cron` and are checked with `cron::validate_cron_expression`; wsgi supersedes web.
- `src/cron/`: `CronScheduler`, `CronJob`, `validate_cron_expression`. 5-field cron, interpreted in UTC.
- `src/domain.rs`: `Domain` newtype, `parse_domains`: only lowercase alnum, `-`, `.`, optional leading `*` label, so no config syntax gets into router files.
- `src/backend.rs`, `src/route_plan.rs`: `Backend` (Tcp or Unix, `Display` is the router form), `RoutePlan`, `HttpsPolicy` (`only`/`also_plain_http`/`plain_http_only`, serde, sent to the router helper).
- `src/ssh_keys.rs`, `src/authorized_keys.rs`, `src/public_key.rs`: deploy-key management. `setup_authorized_keys(_in)` appends with forced `command=` and dirs 700/files 600; `RIKU_KEY_MARKER` (`FINGERPRINT=`) marks riku's own lines; `parse_public_keys` keeps only a known key type plus the base64 blob, dropping options and comments.
- `src/resource_limits/`: `ResourceLimits::from_env` / `with_app_env` / `apply` (setrlimit; `RLIMIT_NPROC` only on Linux) / `summary`. `from_env` reads the server `RIKU_MAX_*` from the process env; `with_app_env` puts an app env's `RIKU_MAX_*` (its `limits.max_*` settings) over them with the same parser. A `_MB` value too large for a `u64` byte count is ignored like an unparsable one. Every rlimit user (worker spawn, cron, runtime build, preflight/release, `riku run`) goes through `with_app_env`.
- `src/spawn.rs`: `spawn_retrying_etxtbsy`, `output_retrying_etxtbsy`: retry a just-written script's exec.
- `src/process_util.rs`: `get_free_port`, `validate_node_version`.
- `src/deploy_logger.rs`: `DeployLogger` timestamped log plus rail output (`step`, `detail`, `log_warn`, `log_error`, `log_raw` for the file only); path comes from `RikuPaths::deploy_log_file`.
- `src/log_stamp.rs`: the time at the front of app log lines. `stamp_line` writes `<UTC to the second, Z> <text>` (supervisor worker capture and container copy); `split_stamp` reads that and the deploy log's `[<local with offset>] ` prefix back, `None` for an unstamped line. Readers: `riku logs` (`apps/logs/tail.rs`, local `HH:MM:SS` before the worker) and the dashboard log stream.
- `src/display/`: every user facing line, clack style. `rail.rs` `intro` (`┌`), `step_done` (`◇`), `warn` (`▲`, stderr), `error`/`step_failed` (`■`, stderr), `detail`/`detail_err` (`│`), `outro` (`└`), `summary` (aligned key/value block after the outro), `emit` (one pre rendered block on a chosen stream, write errors ignored), pure `render_line`/`render_summary` for tests; `style.rs` `Stream::colour` (color only when that stream is a terminal and `NO_COLOR` is unset or empty) and `paint`; `mod.rs` only declares the submodules and re-exports, its doc table lists which function prints which line on which stream; `tail.rs` `OutputTail` (last 15 lines of a streamed command) and `for_each_line` (a child's pipe read line by line, bad UTF-8 replaced, lines over 64 KiB split; used by riku-plugins `tee_output` and riku-container `run_teed`); `table.rs` `format_table`, `print_table`, `print_table_with_title` (tables keep their column form). Contract: no new crates (linked by `rk`); machine readable output (agent JSON, `logs`) never goes through here.
- `src/outbound_ip.rs`: `detect_outbound_ip` (UDP connect to TEST-NET-1, no packet sent; may be private), used by init's fallback domain and the push summary's port and path URLs; `public_v4` (private, shared, loopback, link-local refused), used by init's `server_ip.rs` and the push summary's `(LAN)` label.
- `src/listening.rs`: `listening_ports` (TCP LISTEN ports from `/proc/net/tcp{,6}`, empty off Linux), used by port mode in riku-deploy and the router helper's bind check.
- `src/token.rs`, `src/secure.rs`: `generate_token`; `constant_time_eq`.
- `src/root_binary.rs`: `ROOT_BINARY` = `/usr/local/bin/riku`, the one server install path.

Gotchas:
- `warn`, `error`, `step_failed` and `detail_err` print on stderr, everything else on stdout; a help block under a warning uses `detail_err` so it stays on the warning's stream. `exit_if_invalid` prints terminal hints on a bad or unknown app name before returning its error; fine in CLI. Services and JSON interfaces (the agent commands) use `existing_app`; the dashboard (`known_app`, 404) and the supervisor control plane (`CliControlActions`) check the app before calling an `apps::cmd_*` that uses it, so no hints reach their output.
- `lib.rs` module list in the doc comment is incomplete; the `pub mod` lines are authoritative.
- Doc comments in `procfile.rs` still name `crate::supervisor::cron`; the cron engine now lives in `riku-util/src/cron/`.

## riku-config
Job: repository layer: resolves every riku path, reads host settings files and per app `riku.toml`. Depends on: riku-util. Used by: riku-caddy, riku-cli, riku-container, riku-dashboard, riku-deploy, riku-nginx, riku-plugins, riku-route, riku-supervisor, riku. Not linked by `rk` or riku-args.
Entry: `RikuPaths::from_env`, `RikuPaths::from_dirs`, `Router::load` (`src/lib.rs`, `src/router.rs`).

- `src/lib.rs`: `RikuPaths` (all dirs under `$RIKU_ROOT`, default `$HOME/.riku`), host path constants (defined in `host_paths.rs`, re-exported: `SOCKET_ROOT`, `ROUTER_SOCKET`, `CADDY_SITE_ROOT`, `NGINX_SITE_ROOT`, `CERT_ROOT`, `ACME_WEBROOT`, `STATIC_ROOT`), defaults (`RIKU_WORKER_TIMEOUT`, `RIKU_WORKER_GRACE_PERIOD`, `RIKU_MAX_RESTARTS`). `RikuPaths::for_tests(root)` is public (not cfg(test)) so other crates' tests can use it; it keeps nginx, socket, caddy and acme paths inside `root`.
- `src/root_dirs.rs`: validates `HOME` and `RIKU_ROOT`: absolute, no `..`. Only path inputs taken from env.
- `src/router.rs`: `Router` (Nginx default, Caddy, Plugin(name)), `stored`, `load`, `save`. `stored`: settings.toml `[router] name`, else `None`; `load` is `stored` or nginx; an invalid settings.toml is an error. `save` writes settings.toml. The engine choice is `ServerSettings.engine.program`, read by its callers directly.
- `src/app_config.rs`: the one app config loader. `load_env` merges repo `riku.toml`, ENV, server override (later wins) into `AppEnv { env }`; an ENV line whose key is a settings table key is dropped, so riku settings come only from the two `riku.toml` files; a `RIKU_<NAME>_VERSION` ENV line stays an app env var but the repo `[runtime] version` wins over it; `runtime_versions` gives the version keys the two `riku.toml` files set, and `runtime_plugin_env` is the env a runtime plugin runs with, its own version key taken only from them (used by riku-deploy `procfile_deploy::runtime_env_for` for build, `env`, `start` and `destroy`, and by `deploy_env` for the node version warning); `load_processes` gives repo `[processes]`/`[cron]` or the Procfile, never both; `load_cron_entries` gives the cron jobs as an ordered list (Procfile `cron:` lines may repeat, so it scans lines). A server override `false` flag removes the key (`AppSettings::cleared_env`). `RikuPaths::app_settings_repo`/`app_settings_override` (lib.rs) name the two files.
- `src/app_settings/`: `riku.toml` (repo file or server override). `mod.rs` `AppSettings::{parse, load, env, processes}`, `Source` (Repo, Server); `keys.rs` `KEYS` table `section.name` to `RIKU_*` env key with `Kind` and `Scope` (only keys something reads; user docs in docs/docs/riku-toml.md); `values.rs` type checks, repo charset, `limits.isolation_root` path shape (absolute, not `/`, no `..`, `. - _ /` only), rendering (false `Flag` omitted, `Bool` renders "false"); `processes.rs` `[processes]`/`[cron]` (cron kinds `cron-<name>`); `parse.rs` section walk; `location.rs` file:line errors that never echo a value; `edit.rs` `set`, `unset`, `get`, `entries`, `to_toml`, `from_env`.
- `src/settings/`: `<root>/settings.toml`. `mod.rs` `ServerSettings { router, engine, routing }`, `parse`, `load`, strict: unknown key/section, wrong type, bad duration (`30s|m|h`) fail with key and file in the message; `engine.rs` `EngineSettings` (program plus time limits); `routing.rs` `RoutingSettings { fallback_domain, server_ip (IPv4 only), shared_port, port_range, present }` (`present` false means the section is missing and the defaults apply; `add_routing_section` reads it), `FallbackPattern::expand` and `as_str` (result checked as a `Domain`), `PortRange`, `routing_section` (text from `templates/settings_routing.toml.txt`, so no naming service is in the code); `save.rs` `save_key` patches one key, re-parses before replacing the file (comments are lost), `add_routing_section` appends `[routing]` with comments when missing.
- `src/nginx_host.rs`: `NginxHostPaths` (`include_file`; `from_env` honors `RIKU_NGINX_HOST_INCLUDE`, `system()` ignores it).
- `src/own_cert.rs`: `OWN_CERT_SUFFIX`, `has_own_cert(paths, app)`: the `<nginx_root>/<app>.own-cert` marker for an app that serves a certificate its owner supplied (pair in `<app>.key` and `<app>.fullchain.crt`).
- `src/program.rs`: `installed_program` (path or `None`) and `find_program` over `$PATH` plus fixed system dirs (including `/snap/bin`). `src/reload_programs.rs`: `ReloadPrograms` (systemctl, caddy, nginx), replaced by mock scripts in tests.

Gotchas:
- Root init must use `NginxHostPaths::system`, never `from_env`, because `sudo -E` keeps the caller's env.
- `socket_root`, `caddy_root`, `acme_root`, `static_root`, `router_socket` are NOT taken from the environment on purpose; do not add env overrides.
- Router, engine and settings are files, not env vars, because git push deploys and the post-receive hook run with no riku env.
- `RIKU_ACME_ROOT` is read inside `RikuPaths::with_nginx_host` (lib.rs).
- Tests are in `src/tests.rs` and `*_tests.rs` siblings.

## riku-http
Job: one blocking reqwest client builder with rustls on ring. Depends on: none. Used by: riku-cli, riku-deploy, riku-supervisor.
Entry: `blocking_client_builder` (`src/lib.rs`).

- `src/lib.rs`: `blocking_client_builder` installs ring as the process rustls provider (ignores "already installed") and returns `reqwest::blocking::Client::builder()`.

Gotchas:
- reqwest is built with `rustls-no-provider`, so any client built without this function panics, even for plain http. Always use this builder.
- Separate from riku-util so `rk` never links reqwest.

## riku-error
Job: typed deploy errors. Depends on: none. Used by: riku-deploy, riku-plugins, riku-supervisor, riku.
Entry: `DeployError` (`src/lib.rs`).

- `src/lib.rs`: `DeployError::DeployInProgress(app)` (callers map to 409 and downcast with `anyhow::Error::downcast_ref`), `DeployError::ResourceExhausted(msg)` built by `resource_exhausted(stage, command, cause)`, a multi-line diagnostic that names `RIKU_MAX_MEMORY_MB` and `RIKU_MAX_CPU_SECONDS`.

Gotchas:
- Callers detect these through `downcast_ref::<DeployError>()` on an `anyhow::Error`; wrapping with `.context()` still works, converting to a string loses it.
- The remedy text hardcodes limit names and defaults (512 MB, 3600 s); keep it in step with `riku-util/src/resource_limits/mod.rs`.
- Inline `mod tests` at the bottom of `src/lib.rs` (not a `_tests.rs` sibling).

## riku-plugin-java
Job: runtime plugin binary for Maven and Gradle apps. Depends on: none. Used by: nobody; shipped as release asset `riku-plugin-java-<target>`, installed by `riku install-plugins --plugins java`.
Entry: `fn main` in `src/main.rs`, same argv[1] protocol as the shell runtime plugins.

- `src/main.rs`: `detect` (exit 0 if `pom.xml` or `build.gradle`), `build` (`mvn package -DskipTests --batch-mode`, or `./gradlew`/`gradle build -x test`), `env` prints `JAVA_OPTS=-Xmx512m`, `start` prints `java $JAVA_OPTS -jar target/*.jar` (Maven) or `build/libs/*.jar`, `destroy` no-op. Reads `RIKU_APP_PATH` (default `.`).

Gotchas:
- `start` prints a glob jar path; with more than one jar in `target/` or `build/libs/` (for example plain plus `-sources`) the command breaks.
- Maven is checked first when both build files exist.

## riku-plugin-clojure
Job: runtime plugin binary for Leiningen and Clojure CLI apps. Depends on: none. Used by: nobody; release asset `riku-plugin-clojure-<target>`, installed by `riku install-plugins --plugins clojure`.
Entry: `fn main` in `src/main.rs`.

- `src/main.rs`: `detect` (`project.clj` or `deps.edn`), `build` (`lein uberjar`; for deps.edn `clojure -T:build uber` only if `build.clj` exists, else no-op), `env` prints `JVM_OPTS=-Xmx512m`, `start` prints `java $JVM_OPTS -jar target/uberjar/*.jar` (lein) or `clojure -M -m core` (deps.edn), `destroy` no-op.

Gotchas:
- deps.edn `start` assumes the main namespace is `core`; apps with another name must override via Procfile.

## plugins/ (bundled runtime and event plugins)
Single-file bash runtime plugins, no extension: `node`, `python`, `ruby`, `go`, `rust-lang`. Each takes argv[1] in `detect|build|env|start|destroy`, reads `RIKU_APP_PATH` (fallback cwd). `detect` exit 0 means "mine". `env` prints KEY=VALUE lines, `start` prints the default start command. Triggers: node `package.json`; python `requirements.txt`/`pyproject.toml`/`setup.py`; ruby `Gemfile`; go `go.mod` or `*.go`; rust-lang `Cargo.toml`. node builds with nub (npm fallback, prints the install hint) after checking the server's `node --version` against `RIKU_NODE_VERSION` when set (major, major.minor, exact, `.x` allowed; a mismatch fails naming both); python builds with uv for `RIKU_PYTHON_VERSION` when set (`--python`; pip needs `python<version>` and fails naming the key; a venv made for another version is made again) (`uv sync --locked` with a `uv.lock`, else `uv pip install`; pip fallback with a hint) and a failed install stops the build.
- `plugins/riku-notify/`: event bundle (not a runtime). `riku-plugin.toml` (type notifier, subscribes `app.restarted`, `app.failed`, mode observe, network capability) and `bin/on-event` (argv `on_event`, JSON envelope on stdin, posts to webhook/Discord/Slack/Telegram per `RIKU_NOTIFY_*` env vars).
- Built into riku: the five runtimes and `riku-notify` are embedded with `include_bytes!` in `crates/riku-cli/src/apps/embedded_plugins.rs` and written out by `riku install-plugins`; java and clojure are downloaded from this riku's release tag and checked against their `.sha256` (`plugin_download.rs`), for the triple riku itself was built for (`RIKU_TARGET` from `crates/riku-cli/build.rs`, checked against `RELEASE_TRIPLES`; a test keeps that list equal to the `release.yml` matrix). A new plugin here must be added to `EMBEDDED` and to `riku_util::runtime_markers::BUNDLED_RUNTIMES` (a test checks they agree).
- Runtime selection: `RIKU_RUNTIME` override, else first alphabetical `detect` exit 0 (see riku-plugins).

## templates/ (nginx Tera templates)
Rendered only by riku-nginx. Embedded at compile time with `include_str!` and registered in `crates/riku-nginx/src/template.rs` (`register_templates`); a new template must be added to that list. The site entry template is chosen in `crates/riku-nginx/src/route_site.rs`.
- Entry templates: `nginx.conf.tera` (plain proxy site, port 80), `nginx_wsgi.conf.tera` (uWSGI site on the external port), `nginx_portmap.conf.tera` (proxy on a mapped external port), `nginx_static.conf.tera` (static root), `nginx_https_only.conf.tera` (port 80 redirect plus ACME location, used when HTTPS only).
- Fragments (via `{% include %}`): `nginx_upstream.conf.tera` (upstream block from `RIKU_BACKENDS`), `nginx_common.conf.tera` (body limits, `.git` block unless `RIKU_NGINX_ALLOW_GIT_FOLDERS`), `nginx_site_locations.conf.tera` (ACME plus static aliases), `nginx_acme.conf.tera` (http-01 location, `ACME_WWW`), `nginx_uwsgi.conf.tera` (uwsgi_pass and written-out uwsgi params).
- Values are sanitized in riku-nginx before they reach a template; backend addresses go through `backend_address`.
- There is no Caddy template here; Caddy site files are built in code (riku-caddy).

## Release and CI
- `.github/workflows/ci.yml`: tests, clippy, dashboard checks, integration and Docker e2e on push and PR. It publishes nothing.
- `.github/workflows/release.yml`: on a `v*` tag. Checks the tag matches the workspace version, builds every target, publishes `<bin>-<platform>.tar.gz` plus `.sha256` and the raw `riku-plugin-<name>-<triple>` plugins. ## riku-bundle
Job: plugin bundle manifest (`riku-plugin.toml`) parsing/validation and Ed25519 signing. No server knowledge, usable by `rk`. Depends on: none. Used by: riku-plugins, riku-deploy, riku-remote, riku-client.
Entry: `PluginManifest::from_dir` / `from_toml_str` (`src/manifest.rs`), `RouterSection`, `signing::{Keypair, verify, decode_pubkey}`, consts `RIKU_PLUGIN_API` (1), `ROUTER_PROTOCOL` (2) in `src/lib.rs`.

Contract: `validate` refuses `api != RIKU_PLUGIN_API`, names outside `[A-Za-z0-9_-]`, any `entry` that is empty, absolute or has `..`, and any `events.mode` other than `observe`. `from_toml_str` always validates.

- `src/signing.rs`: hex Ed25519 keypair, `verify(message, signature, pubkey) -> bool`. Contract: a signature covers the entry bytes only, not the rest of the bundle; trust in the key is the caller's job (keyring lives in riku-plugins).

Gotchas:
- `manifest.checksum` and `signature` are only data here; the install gate that enforces them is `riku-plugins/src/install.rs`.

## riku-caddy
Job: render and locate Caddy site files for the Caddy router. Depends on: riku-config, riku-util. Used by: riku-route, riku-cli.
Entry: `render_site`, `site_path` (`src/site.rs`); `import_line`, `has_import`, `SYSTEM_CADDYFILE`, `ADMIN_ADDRESS` (`src/host.rs`).

- `src/site.rs`: `render_site_with_tls(app, &RoutePlan, Option<&TlsFiles>)` adds `tls "<cert>" "<key>"` (caller supplied paths, refused with control chars, quotes or backslash) so Caddy does not issue for that site; `render_site(app, &RoutePlan)` is the same without it and gives `addr1, addr2 { reverse_proxy up1 up2 }`, plus `http://:<port>` for `RoutePlan.open_port`. `paths.rs` `render_paths` for the shared path site (`redir /<app> /<app>/`, `handle_path /<app>/*` with `X-Forwarded-Prefix`). Contract: errors on no backend or any unix backend (TCP only); `HttpsPolicy::AlsoPlainHttp` adds an `http://<domain>` address per domain; `HttpsPolicy::PlainHttpOnly` lists only the `http://<domain>` addresses, so Caddy asks for no certificate. `site_path` is `paths.caddy_root/<app>.caddy`.
- `src/host.rs`: the single `import` line the system Caddyfile needs (`/etc/caddy/Caddyfile`), and the admin socket address `unix//run/caddy/admin.sock`.

Gotchas:
- This crate never writes a file or reloads Caddy. The helper in riku-route does both as root (`riku-route/src/caddy_apply.rs`).

## riku-nginx
Job: nginx config rendering from a checked route, plus what the deploy user still does: publish static files, issue certs. Depends on: riku-config, riku-util. Used by: riku-route, riku-deploy, riku-cli, riku.
Entry: `render_route_site`, `RouteSite`, `SiteFiles`, `SiteShape` (`src/route_site.rs`); `default_backends`, `bind_address`, `upstream_port_number` (`src/backends.rs`); `publish_static`, `remove_static`, `static_locations` (`src/static_site.rs`); `ensure_ssl_certificates` (`src/ssl.rs`); `render_paths_site`, `PathsSite`, `PathApp` (`src/paths_site.rs`, template `nginx_paths.conf.tera`: one `location /<app>/` per app, prefix stripped, `X-Forwarded-Prefix`); `issue_single` (`src/ssl_single.rs`); `remove_deploy_files` (`src/remove.rs`); `breaks_directive` (`src/sanitize.rs`); `write_include_file`, `include_line`, `includes_riku_sites`, `site_path` (the helper's `/etc/riku/nginx/<app>.conf`) (`src/host.rs`); `needs_catch_all` (`src/default_server.rs`); `warn_about_app_nginx_configs` (`src/lib.rs`).

- `src/route_site.rs`: Tera render from typed `RouteSite` and `SiteFiles`; `open_port` adds `listen <port>` lines (`nginx_open_port.conf.tera`; with no domains the site listens only there as `server_name _`); `also_tls` adds a 443 listener with no redirect (`nginx_also_tls.conf.tera`, included by the plain and portmap templates) for a fallback domain that has a pair. Contract: runs as root in the helper, so reads no file, runs no program; unquoted values still go through the directive character refusal.
- `src/template.rs`: registers the ten `templates/nginx*.conf.tera` files via `include_str!`; `backend_address` refuses directive characters and whitespace in a unix socket path.
- `src/sanitize.rs`: one deny-list `breaks_directive`, shared with riku-route's gate so gate and renderer cannot disagree.
- `src/backends.rs`: reads ENV (`RIKU_BIND_ADDRESS`, `RIKU_UPSTREAM_PORT`, `PORT`, `RIKU_NGINX_PORTMAP`) into backends; the socket is always `<socket_root>/<app>.sock` (riku-deploy `router::configure` and `router::apply` refuse `RIKU_NGINX_SOCKET` first). Contract: a present but malformed bind address or port is an error; `localhost` is not accepted. `upstream_name` is `riku_<hex of app bytes>` (nginx compares upstream names case-insensitively).
- `src/static_site.rs`, `src/static_copy.rs`: copy `RIKU_NGINX_STATIC` / `RIKU_NGINX_STATIC_PATHS` out of the checkout to `<static_root>/<app>~<stamp>` and swap the `<app>` symlink. Contract: every path and symlink canonicalized and must stay inside the checkout; dirs `2750`, files `0640`.
- `src/ssl.rs`: `ensure_ssl_certificates`: an existing pair is kept, else acme.sh, else self-signed via openssl. Writes `<nginx_root>/<app>.{key,crt,fullchain.crt}`. Contract: validates app name; key always chmod `0600`. An app with the `<app>.own-cert` marker (`riku_config::own_cert`) is never issued, self-signed or hooked: `own_pair_ready` returns true when its key and chain exist and errors when they do not.
- `src/acme.rs`: acme.sh calls (http-01 files in `acme_root`, umask 027). `try_acme_certificates` issues one certificate naming every domain; when that fails it falls back to the first domain that passes alone and names the uncovered ones. `install_renew_hook` sets `riku router-renew` as the reload command on the certificate acme.sh has (first domain it accepts), then writes `<app>.renew-hook` so deploys skip it.
- `src/ssl_single.rs`: `issue_single` for a fallback domain: reuses an existing key and full chain, else one acme.sh issue; never self-signed (a failure means plain HTTP). An own certificate (marker) is reused through `ssl::own_pair_ready`, for any name.
- `src/host.rs`, `src/default_server.rs`: root-owned include file holding one `include /etc/riku/nginx/*.conf;` and optionally a catch-all server when the host has no port 80 default.
- `src/remove.rs`: removes the deploy user's cert files (including the `own-cert` marker) and sockets only.
- `src/test_support.rs`: test helper.

Gotchas:
- Two cert locations: this crate writes certs under `nginx_root` (deploy user); the helper writes the TLS pair it receives under `cert_root` (riku-route `nginx_render.rs`).
- The `ensure_ssl_certificates` return bool is "cert pair is usable", not "issued by acme".
- Apps cannot ship their own nginx config; `warn_about_app_nginx_configs` only warns about `nginx.conf` and three variants.

## riku-route
Job: the router helper's protocol, route gate, and nginx/Caddy apply as root. Depends on: riku-caddy, riku-config, riku-container, riku-nginx, riku-util. Used by: riku, riku-cli, riku-deploy.
Entry: `check_nginx_route`, `check_caddy_route`, `CheckedRoute` (`src/check.rs`); `Request`, `Reply`, `Stage`, `RouterKind`, `parse_request`, `encode_request`, `parse_reply`, `encode_reply`, `PROTOCOL_VERSION` (`src/protocol.rs`); `Route`, `RouteBackend`, `SiteKind`, `Listen`, `Tls` (`src/schema.rs`); `run`, `bind_socket`, `restrict_umask` (`src/listen.rs`); `serve_one`, `REQUEST_BUDGET` (`src/server.rs`); `read_bounded`, `MAX_MESSAGE_BYTES` (`src/bounded.rs`); `answer` (`src/answer.rs`); `apply_nginx`, `remove_nginx`, `NginxRoots`; `apply_caddy`, `remove_caddy`, `CaddyRoots`.

- `src/schema.rs`: wire route structs, all `deny_unknown_fields`. Parsed, not checked; only the gate says safe. `Route.open_port` (port mode, `null` when unset); the gate refuses it below 1024, at 2019, and on uWSGI or static sites. `port_wait.rs` waits up to 2 s after a reload for `open_port` to be in LISTEN and the apply restores the old files when it is not. `Request::ApplyPaths { router, listen, apps: Vec<PathApp> }` replaces the shared path site: `paths_check.rs` (privileged port, `AppName`, duplicates, backend rule), `paths_apply.rs` writes `_paths.conf` or `_paths.caddy` (no app name can start with `_`), waits for the shared port, restores on failure; an empty list removes the file.
- `src/protocol.rs`: one JSON object per request/reply, `"v": 1`, ops `apply`, `remove`, `status`. Missing `router` means nginx. Refuses other versions.
- `src/check.rs`, `check_text.rs`, `check_tls.rs`: the single gate. `check_tls` is also `pub` (`riku_route::check_tls`): riku-cli's `riku certs set` uses it to prove a pasted chain and key belong together. Domains lowercase `Domain` or `_`; at least one domain; backends must be loopback TCP or `unix_copy >= 1`; listen port 80 or >= 1024; TLS pair re-encoded from parsed DER (cert chain in one field, exactly one matching key in the other); `https: only` needs TLS (nginx). Caddy takes a TLS pair (checked and re-encoded the same way) but refuses `allow_git_folders`, custom listen, unix/wsgi/portmap/static, and `_`.
- `src/listen.rs`, `src/server.rs`, `src/bounded.rs`: socket root:deploy-group `0660`, bound under umask `0177`. `serve_one` reads `SO_PEERCRED` and silently drops any uid except the deploy user and 0. Input capped at 1 MiB and 10 s, one connection at a time.
- `src/answer.rs`: validates the app name as `AppName`, dispatches to nginx or Caddy side by `RouterKind`.
- `src/nginx_apply.rs`, `nginx_render.rs`, `nginx_roots.rs`, `nginx_run.rs`: snapshot old files, write new, `nginx -t`, reload, restore on any failure. `NginxRoots::production()` uses riku-config constants and picks `systemctl reload` if `SYSTEMD_RUNTIME_DIR` exists, else `nginx -s reload`. Tests pass temp roots.
- `src/caddy_apply.rs`: writes `<site root>/<app>.caddy`, reloads via Caddy admin unix socket, restores previous file if reload fails. `caddy_certs.rs`: an own certificate pair goes to `<site root>/certs/<app>/{fullchain.pem,key.pem}` (files 0640, dirs 2750 so the group stays `caddy`), planned with the site file so a failed reload restores both; the directory is removed when the route has no tls and on `remove_caddy`.
- `src/site_files.rs`: write via `.new` sibling and rename; modes set on the open file, never left to umask; `Snapshot` for rollback. `check_router_dir` runs at the start of both `commit`s (nginx: site root `0755`, cert root `0700`; Caddy: site root and `certs` `2750`): a root that exists but is not a real directory owned by root and writable by root alone stops the write and the reload, naming the dir and the expected mode.
- `src/caddy_test_server.rs`, `test_pems.rs`: test helpers (`test-server` feature / cfg(test)).

Gotchas:
- The gate runs twice by design: the deploy side calls `check_caddy_route` for an early error, the helper calls the gate again on receipt. Never skip the helper-side call.
- `nginx_run::check_config` trusts exit status only; the old deploy-side wrapper accepted "syntax is ok" text.
- No request field is a path. New fields must not become one.

## riku-plugins
Job: plugin system: runtime plugins, hook plugins, manifest bundles (addon/router/events), sandbox, install, marketplace, trust keyring. Depends on: riku-config, riku-util, riku-error, riku-bundle. Used by: riku-cli, riku-dashboard, riku-deploy, riku-supervisor, riku.
Entry: `PluginManager::run_hook`, `PluginHook`, `HookContext` (`src/manager.rs`, `src/hooks.rs`); `runtime::{discover, detect, build, build_with_limits, destroy, get_env, get_start_cmd, parse_env_lines}` (`src/runtime.rs`); `PluginInstaller` (`src/install.rs`); `AddonService` (`src/addon/`); `EventBus` (`src/events/`); `router::run_verb` (`src/router/`); `MarketplaceService`; `bundles::{find_bundles, find_addon, find_router}`; `plugin_data_path`; `Keyring`, `Lockfile`.

- `src/discovery.rs`: `validate_plugin_name` (no `/`, `\`, `..`, empty), `list_plugins` (executable files in `plugin_root`), `plugin_exists`.
- `src/hooks.rs`, `src/manager.rs`: name-based hooks `riku-pre-deploy|pre-build|post-build|post-deploy` in `plugin_root`. Contract: pre-deploy, pre-build, post-build failure or timeout aborts; post-deploy only warns. Runs in its own process group. A hook file without an execute bit is skipped with a `▲` line naming it (as if absent), never chmodded.
- `src/runtime.rs`: runtime plugins are executables in `plugin_root` not named `riku-*`; verbs `detect|build|env|start`. Order: `RIKU_RUNTIME` ENV override, else alphabetical first `detect` exit 0. Hidden files (an interrupted install's `.<name>.<pid>.<serial>.new`) are never plugins. `RIKU_RUNTIME` naming no installed plugin is the typed `MissingRuntime` error.
- `src/runtime_bundles.rs`: `add_runtime_bundles` adds bundle dirs with `type = "runtime"` to `discover`; a plain file wins a name clash.
- `src/executor.rs`: timeout and output helpers. Reads `RIKU_PLUGIN_TIMEOUT` (`plugin_timeout`). Re-exports ETXTBSY-retry spawn from riku-util. `tee_output(child, recent)` streams a child's stdout and stderr under the output rail, both on stdout so an ssh client keeps the order, and feeds the caller's `OutputTail`; `runtime::build` takes that tail too.
- `src/bundles.rs`: finds `riku-plugin.toml` dirs; invalid manifests are skipped with a warning.
- `src/addon/`: `state.rs` instance registry `~/.riku/addons/instances/<instance>.toml`; `dispatch.rs` runs a verb (JSON line on stdin, JSON on stdout); `service.rs` bind/unbind env merge. Contract: bind rewrites only the keys it owns and leaves other ENV lines byte-for-byte.
- `src/events/`: `EventName`, `EventEnvelope`, `EventBus::emit` (verb `on_event`; `with_subscriber_env` adds variables for every subscriber, so tests never set process env). Observe mode only; subscriber failure never fatal. Blocking a deploy is a `riku-pre-deploy` hook, not an event.
- `src/router/`: raw verb dispatch (`configure`/`reload`) to a third party router plugin; stdout discarded, success is exit code. Active router is `[router] name` in `settings.toml` (default `nginx`); that choice lives in riku-config and riku-deploy.
- `src/sandbox/`: Landlock (fs and TCP net, kernel >= 6.7) plus `PR_SET_NO_NEW_PRIVS` applied in `pre_exec` from the manifest `[capabilities]`. `writes` names `app_dir|data_dir|env_dir` resolved in `paths.rs`. Linux only, otherwise runs unconfined with a stderr warning.
- `src/install.rs`, `lockfile.rs`, `signing.rs`: install from local dir or git URL; pinned `checksum` mismatch rejected; a `signature` must verify against a key in `~/.riku/trusted-keys.toml` else rejected. Lockfile `~/.riku/riku-plugins.lock`. A bundle with neither checksum nor signature installs, flagged unverified.
- `src/marketplace/`: `~/.riku/marketplaces.toml`, clones to `~/.riku/marketplaces/<name>/`, index `marketplace.toml`; payload pulled only on `add`.
- `src/plugin_data.rs`: per-plugin scratch dir `data_root/plugin-data/<name>/`, created lazily.

Gotchas:
- Two plugin systems coexist: name-based hooks/runtimes (no manifest, no sandbox) and manifest bundles (sandboxed). The manifestless ones are spawned by `manager.rs`/`runtime.rs`, not through `sandbox::harden`.
- `PluginManager::run_hook` sets the exec bit on a hook file that lacks it instead of skipping it.
- Sandbox callers: addon dispatch, events bus, install (`harden` in `install.rs`). A new seam must call `sandbox::harden` or it runs unconfined.
- Env keys read here: `RIKU_PLUGIN_TIMEOUT`. Env passed to plugins: `RIKU_APP`, `RIKU_APP_PATH`, `RIKU_ENV_PATH`, `RIKU_ROOT`, `RIKU_HOOK`, `RIKU_DETECTED_RUNTIME`(hooks, runtimes), plus `RIKU_PLUGIN_NAME`, `RIKU_PLUGIN_DATA_PATH`, `RIKU_ADDON_DATA_PATH` appear in bundle dispatch code.

## riku-supervisor
Job: process supervisor daemon: spawns and restarts workers from TOML configs, health checks, cron, container watch, stats, log rotation, loopback HTTP health/control plane. Depends on: riku-config, riku-util, riku-http, riku-error, riku-plugins, riku-container. Used by: riku-cli, riku-deploy, riku.
Entry: `Supervisor::new`, `with_actions`, `run` (`src/daemon/`); `WorkerConfig`, `create_worker_config`, `app_worker_configs` (`src/config/`); `ProcessManager` (`src/process/mod.rs`); `read_stats_file` (`src/stats/repository.rs`); `ControlActions` trait (`src/health/actions.rs`); `start_health_server` (`src/health/mod.rs`); `app_has_live_worker`, `process_has_live_worker` (`src/process/pid_file.rs`); `setup_signal_handlers`, `is_running` (`src/lib.rs`).

- `src/config/`: worker TOML model (`[worker] app kind command ordinal`, `[env]`, `[options]`, health check). `limits.rs` keeps the two kernel settings apart: `WorkerLimits` (`[options.limits]`, from `RIKU_ISOLATION_MAX_MEMORY_MB`/`_MAX_PIDS`/`_CPU_QUOTA_US`/`_CPU_PERIOD_US`, `None` unless memory, quota or pids is set) gives the worker its own cgroup and nothing else; `Sandbox` (`[options.isolation]`, from `RIKU_ISOLATION_ROOT`, the server only `limits.isolation_root` setting) adds the chroot plus PID/mount/net namespaces; `Sandbox::check_root` refuses a root without the shape of riku-config `app_settings::is_isolation_root` (the same rule `riku settings set` applies) or that is not an existing directory, and `spawn_process` calls it before anything else. `[options]` is a plain derive; a missing `timeout`, `grace_period` or `max_restarts` reads as the riku-config default. `ownership.rs` decides which `.toml` files in `workers-available/` or `workers-enabled/` belong to an app, by `[worker] app`, falling back to name only for `<app>@<kind>.<n>` files (unowned means not deleted).

Contract: engine output and labels untrusted; names pass as validated types; log files opened `O_NOFOLLOW`, path under log root, output capped per stream. `mock_*`, `test_ticks.rs` are test helpers.

- `src/stats/`: `StatsManager` in memory, `write_stats_to_file` writes `stats.json` (5 s), `repository.rs` is the CLI side reader, `resources.rs` `ProcessTable` (one `/proc/*/stat` snapshot per tick on Linux, empty elsewhere) whose `tree_usage` sums a worker's pid and every descendant; a worker with a cgroup reports `cgroups/usage.rs` `WorkerCgroup::usage` (`memory.current`, `cpu.stat` `usage_usec`) instead (`SpawnedProcess::resource_usage`).
- `src/cgroups/`: cgroup v2 under the supervisor's own delegated cgroup (`0::` line of `/proc/self/cgroup`, unit needs `Delegate=yes`). `tree.rs` `take_over_own` at startup moves the supervisor to `<own>/supervisor` and enables `+memory +cpu +pids` in `<own>` and `<own>/apps`; `limits.rs` holds `CgroupLimits` and how each limit file is written; `WorkerCgroup::provision` makes `<own>/apps/<app>@<kind>.<n>/` and writes `memory.max`, `cpu.max`, `pids.max` for the limits set and puts an unset one back to unlimited (`max`, `max <period>`) when its controller is delegated and the file exists, so a reused dir keeps no stale limit; a memory limit also writes `memory.swap.max` 0 where that file exists (swap accounting on), refusing a limit whose controller `take_over` found missing (`CgroupTree::missing_controllers`). Without delegation `startup_diagnostic` is printed and workers that set a resource limit or a sandbox refuse to start (`process/worker_cgroup.rs`).
- `src/log_rotation/`: size based rotation, run every 300 s.
- `src/lib.rs`: signal handlers, SIGHUP listener, re-exports `cron` and `resource_limits` from riku-util.

Gotchas:
- The supervisor is a lower crate: it must not call riku-cli or riku-deploy; behaviour reaches it through `ControlActions` injected by the binary.
- The main loop is single threaded; `spawn_process` must not block (the reason isolation is a separate exec, see `process/isolation/mod.rs`).
- A worker config runs only if its filename equals `WorkerName::file_name()` of its `[worker]` table (`daemon/config_file.rs`); a misnamed one is logged and ignored.
- `RIKU_ENV` defaults to production: missing cgroup v2 writes an error to stderr; set `development` or `dev` to downgrade it to a warning (`daemon/startup.rs`).
- Health server bind failure and cgroup check failure are non-fatal; PID lock failure is fatal.
- Env read: `RIKU_ENV`, `RIKU_HEALTH_PORT`, `RIKU_DASHBOARD_ORIGIN`; limits via `ResourceLimits::from_env` (`RIKU_MAX_*`, `RIKU_ISOLATION_*`).

## riku-deploy
Job: deploy orchestration (service layer): sync checkout, build, start workers or containers, route, release history, backup. Depends on: riku-bundle, riku-config, riku-util, riku-http, riku-error, riku-nginx, riku-route, riku-plugins, riku-supervisor, riku-container. Used by: riku, riku-cli, riku-dashboard.
Entry: `do_deploy`, `rollback` (src/lib.rs); `spawn_app` (supervisor_ctl.rs); `create_workers_generic` (workers.rs); `router::{configure, apply, remove, renew, check, build_route}`; `containers::*` (deploy_containers, restart_service, scale_service, stop_service, destroy_containers, update_service, restart_copy, open_engine); `lock::{acquire, acquire_for_deploy, acquire_for_restart, is_locked}`; `ReleaseLog`; `BackupService`.

- `src/lib.rs`: `do_deploy`. Takes the deploy lock and opens the deploy log (`prepare`), runs `pipeline::run`, and on failure resets the checkout to the last recorded release (`checkout_restore.rs` `restore_last_release`; nothing on a first deploy, nothing once `DeployProgress::release_replacing` was called, since the new worker configs or containers run the pushed commit; for a container app `deploy_containers` calls its `replacing` callback only after counts, images and the release command are ready, right before the first copy is replaced) and prints the failure block through `DeployProgress::failed` before returning the error. A failure before the lock (app missing, deploy in progress) is printed as one `■` line. Re-exports dependency crates as `config`, `error`, `nginx`, `plugins`, `supervisor`, `util` (crate-internal aliases). Contract: container apps refuse scaling `deltas`; `rollback` redeploys a prior sha from `ReleaseLog`; every `do_deploy` error has already been shown on the rail (the git hook relies on this); after a deploy that failed before its worker configs changed, `apps/<app>` holds the last released commit.
- `src/pipeline.rs`: the deploy steps in order: git sync then the intro naming the commit, ENV, container app vs Procfile app, then `finish_deploy`.
- `src/progress.rs`: `DeployProgress`, the push output on the rail from riku-util `display`: intro `Deploying <app>  <sha> "<subject>"`, one step per `Phase` (Preflight, Runtime, Build, Release, Processes, Route; Build, Release and Preflight carry their duration), outro `Deployed in Ns` with a summary (App, Commit, URL, Workers, Logs). On failure, one block on stdout (`render_failure`): `■  <Phase> failed  <reason>`, then `Deploy failed.` (build output is not repeated, it was streamed already) (plus "The previous release was left as it was." when a release exists and `release_replacing` was not called; the Procfile deploy calls `release_replacing` after `workers::check_workers` passes and `LIVE_ENV` is written, right before the worker configs change; the container deploy calls it before `deploy_containers`, so a failure keeps the checkout the new containers run), and a summary with `rk logs <app> --deploy` and `git push riku <branch>`. A Procfile app without a route (`router::has_route`) gets no URL lines. Runtime plugin detect/build (a missing shipped runtime names `rk plugins install <name>`; an app with `RIKU_NGINX_STATIC` and no matching runtime is told static files need a runtime, since there is no runtime-less static deploy), preflight/release, scaling deltas, workers, router. Gotchas:
- Two worker kinds of copies: Procfile copies are `workers_enabled/<app>@<kind>.<n>.toml`, container copies are engine containers with `riku.*` labels. `rolling/` serves both through `CopyRuntime`, so change ordering rules there once.
- Container apps are detected by `RIKU_RUNTIME=container`, a compose file (`COMPOSE_FILE` in ENV picks another name) or a Containerfile/Dockerfile (`containers/app.rs`). A switch from Procfile to containers parks old workers as `<name>.toml.migrating`.

- `resolve_riku_bin` returns `None` (supervisor not started) when there is no `ROOT_BINARY` and `current_exe()` fails; it never hands a bare `riku` to a `$PATH` lookup.
- Registry login (`containers/images.rs`) stores credentials in the engine user's shared auth file; last login wins across apps.
- `start_copy` re-walks bind sources for symlinks right before `run` (check then use, accepted).
- `RIKU_*` app env keys are not passed to containers (`containers/spec.rs`); the compose project label is dropped.
- Health and probe code only hits 127.0.0.1, forces paths to start with `/`, follows no redirects, ignores proxy env.
- Router is a host singleton from `config::router::Router::load` (settings.toml, default nginx). nginx and Caddy go through the root helper socket; Caddy backends are rewritten to loopback. A plugin must declare router protocol 2.
- `src/README.md` lists `ensure_host_ready` / `router/host_guard.rs`; neither exists in the source.
- Crate comments say `?` is avoided; `#[allow(clippy::question_mark)]` marks that. Unit tests live in sibling `*_tests.rs` files.

Output: intro, one rail line per check (`◇` ok, `▲` warn, `■` fail, all on stdout so a piped report keeps its order) with its detail on `│` lines, outro and a `Checks` summary. Contract: checks are read-only (doctor has no fix mode); exit 1 on any Fail.
- `src/git/`: push path. `receive_pack.rs` (`cmd_git_receive_pack`, `cmd_git_upload_pack`: validates repo name from the ssh command, creates bare repo and hook lazily), `hook.rs` (`cmd_git_hook`: reads `old new ref` lines from stdin, clones on first push, `do_deploy` per ref; a `do_deploy` failure was already printed, so the hook records it and exits 1 without printing it again), `repo.rs` (`post_receive_hook` text), `push_status.rs` (carries a hook failure back to `git push` through a status file named in `STATUS_ENV`; `deploy_result` gives `DeployResult::{Succeeded, Failed, Unknown}`). `receive_pack.rs` `push_outcome` turns that into the exit code and prints only an `Unknown` result, since the hook already showed a failure through git's sideband.
- `src/agent/`: `riku agent` JSON interface for AI agents. `execute.rs` order: state dir, rate limit, scope check, audit log opened before mutating commands, run, audit entry, then a response with an error code returns `Err` so the process exits 1 (a confirmation request exits 0). `auth.rs` `AgentSession::from_flags` (id and scope from forced-command flags only), `check_rate_limit` (flock'd file), `types.rs` `AgentScope` (Readonly default, Staging, Production), `state.rs` (0700 dir, 0600 files, `O_NOFOLLOW`), `confirm.rs` (one-use stop/destroy tokens: 256 random bits, record in the state dir, checked as hex before use, bound to action and app, 5 minute expiry), `audit.rs` (JSON lines), `schema.rs`, `help.rs`, `quiet_stdout.rs` (fd 1 points at stderr while a command runs, so progress from riku and child processes never mixes into the JSON), `commands/` per command.
- `src/plugins/mod.rs`: `riku plugins` output layer over riku-plugins (`PluginInstaller`, `MarketplaceService`, trust keys); `install_route.rs` sends a bare shipped plugin name (`BUNDLED_RUNTIMES`, riku-notify) to `install_runtime`, paths and git sources to the bundle installer, and refuses any other bare name. `src/addon/mod.rs`: `riku addon` over `AddonService`. `src/hooks.rs`: `riku hook list|check`.
- `src/backup.rs`: `riku backup|restore` over `deploy::backup::BackupService`. `src/scp.rs`: runs `scp` in `git_root`. `src/control_actions.rs`: `CliControlActions` implements the supervisor's `ControlActions` trait by calling the same `apps::cmd_*` functions, after `existing_app` for deploy, restart, stop and destroy (so an unknown app is a plain error, without the CLI's terminal hints).
- Tests: sibling `*_tests.rs` files via `#[path]`; cross-crate tests in tests/integration_tests/.

Gotchas:
- Some READMEs under src/ list stale symbols (`container.rs`, `ContainerCmd`, `DeployUser::create_dir`/`chmod` do not exist); trust the code.
- `cmd_hook_check` calls `std::process::exit`, and `cmd_doctor` and `cmd_scp` exit the process too; they do not return to the dispatcher.
- Two ways to install the supervisor unit: `setup/user_service.rs` (plain user) and `setup/system_service.rs` (root init); changes to the unit text usually need both. Both carry `Delegate=yes`, which riku-supervisor `cgroups` needs for worker isolation, and no `MemoryMax`/`CPUQuota` (that would cap all apps together). Both write the unit through `supervisor_binary.rs` `write_unit` (`UnitChange::{Same, Changed}`), run `daemon-reload` (a failed reload fails init before any restart), then ask `action_for` whether to `start` (stopped, or already running the installed binary under unchanged unit text: step says `running`) or `restart` (`/proc/<MainPID>/exe` differs from `ROOT_BINARY` by inode and content, or cannot be read: `restarted (new binary)`; unit text changed: `restarted (unit changed)`; root init only, through `with_groups`: the running process's `/proc/<pid>/status` `Groups:` lacks a gid root init put the deploy user in (`riku-sockets`, the docker socket's group when a member): `restarted (new groups)`), at most one restart per init since every group change runs before this step, so re-running init without a change does not bounce every app. Root decides only from MainPID. `service_main_pid` returns `Result<Option<u32>>`: only exit 0 with `0` is stopped, a failed or garbled `systemctl show` is an error that aborts init rather than reading as stopped (the user manager asked from the root init's env-cleared child is the one exception, read as not running). Before that, as the deploy user (plain init in `user_service.rs`, or the `init --user-steps` child unless `--no-systemd`, which root passes on), `outside_supervisor.rs` `replace_outside_supervisor` finds a supervisor holding the pid file lock that is not the MainPID of the system or the user `riku` unit (any binary, MainPID 0 included), stops it with riku-deploy `stop_supervisor` (30 s wait) and prints a `Supervisor` step; one that does not stop fails init with the pid to kill; when the other scope's unit holds the lock, init fails naming the init to run instead (`sudo riku init` from a plain init). Root never reads or signals from the deploy user's pid file.
- `RIKU_USER` (default `riku`) is read in `setup/deploy_user.rs` and again by `router_helper.rs`; `RIKU_DEFAULT_BRANCH` in `default_branch.rs`.
- `git/hook.rs` deploys only the repo's default branch (its `HEAD`); other branches, tags and deletions are skipped with a message. When the clone or the deploy fails, `deploy_or_roll_back` moves the branch back with `git update-ref <ref> <oldrev> <newrev>` (or `update-ref -d <ref> <newrev>` after a first push), a compare and swap that leaves a branch another push moved, so pushing the same commit again retries. `git/hook_repo.rs` `app_repo` is the app's one repo, `repos/<app>.git`: `receive_pack.rs` maps a push to `<app>` and to `<app>.git` there, `riku apps create` makes it, the hook clones from it and destroy removes it; `check_hook_repo` refuses a hook run whose repo path does not resolve to it directly inside `git_root`. When `HEAD` names a branch that does not exist, the first pushed branch becomes `HEAD`.
- `control_actions.rs` and the dashboard both call `apps::cmd_*`; those functions print to the terminal.
- Agent `secret_keys.rs`: `is_secret` name heuristic and `MASK`; `commands/cmd_config.rs` masks secret values for a readonly scope. Agent `commands/cmd_run.rs`: `run` (production scope, confirm token bound to the exact argv via `confirm::gate`) executes without a shell in the app dir with only PATH, HOME and LIVE_ENV, under `ResourceLimits::from_env().with_app_env` of that env applied in `pre_exec`, stdin closed, 64 KiB cap per stream, process group killed when the command exits or at 300 s, output readers given 2 s before the run returns. `commands/cmd_config_write.rs`: `config:set` and `config:unset` reuse `apps::config_after_set`/`config_after_unset` for validation, then `env_setup::write_env` and `redeploy`; the keys whose value the parsed result changes are checked, and those containing SECRET, PASSWORD, TOKEN, _KEY or DATABASE_URL need a confirm token bound to a SHA-256 of the exact request.
- Files here use `?` in older code; new code follows rule 16 with `#[allow(clippy::question_mark)]`.

## riku-dashboard
Job: embedded Axum server for `riku dashboard`: static UI plus JSON API and SSE log stream. Depends on: riku-config, riku-util, riku-cli, riku-deploy, riku-plugins. Used by: riku (binary).
Entry: `run(paths, bind, token)` (src/lib.rs); prints `riku-dashboard-bound <port>` (`BOUND_PREFIX` from riku-remote) on stdout for remote sessions.

- `src/lib.rs`: `run`, `DashboardState` (paths, optional token). Contract: non-loopback bind requires a token (`--token` or `RIKU_DASHBOARD_TOKEN`); single-threaded tokio runtime.
- `src/session.rs`: `watch`. When stdin is a pipe or socket (a non-interactive ssh command), the server returns once stdin reaches EOF or the parent pid changes, since sshd sends no SIGHUP without a pty. Any other stdin (tty, `/dev/null` from systemd or the `&` in riku-remote `remote_script.rs`) is not followed.
- `src/routes.rs`: `router`, read gate `authorize`, `/healthz`, `/api/state` (from `cli::apps::state_json`), `/api/apps/{app}/releases`. Contract: without a token only loopback `Host` headers pass; with a token, Bearer header or `?token=` is accepted (constant-time compare) and Host is not checked.
- `src/mutations.rs`: `authorize_mutation` (token required, Bearer header only), restart, stop, redeploy, scale, rollback, per-worker restart and delete; `finish`, `run_action` run the CLI functions on `spawn_blocking`; `known_app` (400 invalid, 404 missing) runs first for `run_action`, scale and `appcfg.rs` env edits, so an unknown app is a 404 and the CLI function never runs. `service_mutations.rs`: container service restart, stop, scale.
- `src/appcfg.rs`: env GET and POST, both behind the mutation gate (Bearer token required: ENV holds secrets); POST goes through `config set/unset`. `addons.rs`: addon endpoints via `AddonService`. `market.rs`: marketplace sources, plugin install/remove, trust keyring. `installed.rs`: `/api/plugins`. `system.rs`: `/api/doctor`, backup, restore upload (2 GiB limit on that route only; scratch file under `data_root`). `logs.rs`: SSE tail of `{log_root}/{app}/*.log`; each `log` event is `<file stem>\t<UTC time>\t<text>`, the time the line's own stamp (riku-util `log_stamp`) or empty, and the panel shows no time for an empty one.
- `src/assets.rs`: `/` and `/assets/{*path}`, served from the fixed `ASSETS` table (`include_str!` of `assets/`). Contract: path is a table key, never a filesystem path; public, no data.
- `assets/`: UI with no build step. `index.html`, `app.css`, ES modules in `js/` (`main.js` entry, `poll.js` refresh loop, `api.js` fetch, `state.js`, `page.js`/`card.js`/`card-events.js` rendering, `render/` pure string builders (`workers.js` `imageLabel`: `built` for a `localhost/riku-<hash>` tag, else the reference; no memory bar without `memory_limit_bytes`; `containers.js` `containerRowsHtml` a header row per service (from `/api/state` `services`, else the copies' kinds) with its image label and controls, copies indented under it, and `containerFooterHtml` the release and stop app controls; `meta.js` an unreadable router site shows the router name with the reason in a tooltip), `logs/` drawer and stream, `actions.js`, `scale.js`, `releases.js`, `auth.js`); `js/tests/` node tests; `jsconfig.json` for tsc check.

Gotchas:
- A new JS or CSS file must be added to `ASSETS` in `src/assets.rs` or it is not served (a test enforces this).
- The UI sends the token as `?token=` on reads (EventSource cannot set headers) and keeps it in localStorage; the token can land in URLs and logs.
- `lib.rs` module doc still says "read-only" and "Mutating actions (later)"; mutations exist and are token-gated.
- The Next.js frontend in `dashboard/` proxies to this server; API changes affect both.
